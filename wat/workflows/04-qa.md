# 04 — QA Workflow

## Goal
Adversarially break the package before it ships. The QA agent assumes the coding/design/marketing agents drifted, hallucinated, or padded — and proves or disproves each claim against the source HTML.

## Constraints
- Every "the app does X" claim must cite a line range or selector in `bolt-post.html`.
- Severity ladder: BLOCKER → MAJOR → MINOR → NIT. Anything BLOCKER kills the GO verdict.
- Check pacing math: if the script claims 18–24 min, count words at 145 wpm and verify.
- Check thumbnail readability at small size.
- Check Mass-vs-Bolt differentiator is a *real* difference, not just rewording.

## Done when
- `wat/tmp/qa-report.md` lists every finding with severity, location, and proposed fix.
- Findings are grouped by stage (coding / design / marketing).
- Final line: "VERDICT: GO" or "VERDICT: BLOCKED — fix N items".
