# Workflow 04 — QA Agent

## Goal
Adversarial review. Pillar is new and undocumented — factual accuracy is the #1 risk.

## Inputs
- All Stage 1 outputs (`wat/tmp/*.md`, `wat/tmp/thumbnail.svg`)
- Source HTML for ground-truth checks

## Constraints
- Verify every claim in the script against `pillar.html`. If the script says "4 loads", grep the source for the number.
- Check brand compliance (no emojis unless in app UI strings, candy palette, no enterprise jargon).
- Check pacing: 15-22 min total, no section >4 min without a beat change.
- Check thumbnail readability at 320x180 px (mobile YouTube card).
- Check title CTR mechanics (number? bracket? question?).
- Flag any "this is like Mass Post / Data Wash" claims that confuse the viewer.

## Deliverable
`wat/tmp/qa-report.md` with:
- Pass/Fail per check
- Specific line/file callouts
- Fix recommendations (not just complaints)

## Self-heal
If QA finds a factual error, the final-decision agent applies the fix; QA does not edit source artifacts.
