# Workflow: QA (Adversarial)

## Goal
Pick the upstream outputs apart. Find gaps, weak hooks, factual errors, pacing issues, brand misalignment.

## Inputs
- `wat/tmp/coding-output.md`
- `wat/tmp/marketing-output.md`
- `wat/tmp/thumbnail.svg`
- `wat/tmp/title-cards.md`
- `wat/tmp/visual-spec.md`
- Source: `Logistics-Suite/site/data-wash.html` (cross-check claims)

## Output
- `wat/tmp/qa-report.md`

## Required sections
1. **Factual cross-check** — every feature claim in the script verified against the HTML source (cite line numbers)
2. **Hook strength** — score 1-10, what's weak, what to rewrite
3. **Pacing review** — flag any chapter that's too long/short for utility-app content (target 15–22 min total)
4. **Brand alignment** — thumbnail, title cards, voice consistency
5. **Marketing risk** — titles that overpromise (e.g. "GDPR-safe," "HIPAA-compliant" — Data Wash makes no such legal guarantee)
6. **Accessibility** — chapter timestamps present? captions plan? readable thumbnail at 320px?
7. **GO/NO-GO recommendation** + required fixes vs nice-to-haves

## Adversarial mindset
- Assume a freight broker watches the first 15 seconds and bounces — does the hook earn the next 15?
- Assume YouTube's algorithm shows the thumbnail at mobile size — is it legible?
- Assume the user pastes a real CRM export with weird columns — does the script handle "what if a column doesn't match a pattern?"
