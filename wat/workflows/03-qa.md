# Workflow 03 — QA (Stage 2)

## Goal
Adversarial review of all three parallel outputs. The QA agent reads `coding-output.md`, `title-cards.md`, `visual-spec.md`, `marketing-output.md`, and the SVG thumbnail, then writes `wat/tmp/qa-report.md`.

## Adversarial checklist
1. **Factual accuracy** — cross-check every feature claim against `load-manager.html`. Flag any "ghost feature" (e.g., a setting that doesn't exist, a button labeled wrong).
2. **Pacing** — script must hit 20-26 minutes. Flag dead air, redundant sections, or rushed transitions.
3. **Hook strength** — the first 30 seconds must answer "why should a broker watch this past the ad?" Flag generic openings.
4. **Title/thumbnail alignment** — the thumbnail headline and the chosen YouTube title must read like the same promise. Flag bait-and-switch.
5. **Voice drift** — flag any sentence that sounds like a SaaS pitch deck. Acceptable: "you fire your G2G batch from the dashboard." Unacceptable: "stakeholders can optimize their freight workflow."
6. **Chapter quality** — chapters must be skimmable and search-friendly.
7. **Tag relevance** — tags must be terms a broker would actually search.
8. **Description CTAs** — verify there's a link slot for the Suite landing page and Bay & Bay contact line.

## Output format
`wat/tmp/qa-report.md` with:
- Verdict block (PASS / GO-WITH-FIXES / REWORK)
- Itemized findings (severity: blocker / major / minor / nit)
- Concrete patch instructions for Stage 3
